# E-016 · Three things Ripcord refuses, on-chain (2026-11-06)

`npm run reversals` in `harness/` (`src/reversals.ts`), against Unichain Sepolia and Reactive Lasna, from the project wallet `0x08e7…9111`. Record: `docs/evidence/m2/refusals.json`. Raw receipts for all 16 transactions: `docs/evidence/m2/receipts/`.

## A. A swap that doesn't reach the line: the line holds
Position **#7955**, line **−2134**, exit at or below. A real swap moved the pool tick **−934 → −1124** (Swap event in swap `0x6b67894a…a937a`, block 67,145,473), toward the line but 1,010 ticks short.
- RipcordReactive reacted on Lasna (`trigger` tx `0xb52659be…70421`, block 7,703,931, status 1) and **was billed 0.0119 lREACT** (its balance drop in that block) but emitted no event and requested no callback.
- 10 s later: no `RipcordPulled` for #7955, liquidity **1e21 → 1e21**, vault status **Armed**.

## B. An exit called by anyone but Reactive: reverted
The project wallet called `RipcordVault.exit` on #7955 directly, forging RipcordReactive (`0xA2de…f2B5`) as the injected sender and a crossing tick.
- Mined and **reverted**: tx `0x6f5761d4…052ad` (gas limit 300,000 set so the call lands on-chain).
- Replayed one block earlier, the chain's reason: **`NotAuthorized(0x08e7…9111, 0x775c…66C1)`**: the sender is not Reactive's callback proxy (`onlyServiceProvider`, reactive-lib-omni `AbstractPayer`).
- #7955 still held 1e21 liquidity and stayed Armed. Then its owner disarmed it (`0x03ce4525…7a027`): status **Disarmed**, liquidity 1e21. This also proves C-10's "You can disarm a line at any time" on-chain.

## C. An exit after the owner revoked approval: refused and recorded
Position **#7956**, line **−1184**, exit at or below. The owner revoked the vault's approval (`approve(0x0, 7956)`), then a swap moved the tick **−1124 → −1218**, across the line.
- Lasna pulled the ripcord (`0xb84a9ef2…ab1aa`) and the callback reached the vault, which could not touch the NFT. It caught the failure and recorded **`ExitFailed`** (`0x2fb3cc41…b5a8f`) with the PositionManager's reason **`NotApproved(0x6414…4c98)`** (RipcordVault).
- #7956: liquidity **1e21 → 1e21**, vault status **Failed**. The board shows it CANCELLED with the reason.

## Read corrections
The first run read three values from an RPC node that had not yet served the transaction's block: both post-swap ticks and the status right after the disarm. They were replaced from the chain's own record (Swap events in the receipts; a fresh `lines()` read) and are kept in `refusals.json` under `readCorrections`. The script now reads ticks from the receipt and waits for the block before any state read.
